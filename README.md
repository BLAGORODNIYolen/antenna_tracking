# Эмулятор дрона и наведение антенны — Arduino Mega 2560

Проект из двух независимых частей: `python/` — настольный эмулятор на PySide6;
`firmware/` — прошивка Mega 2560 для 28BYJ-48 + ULN2003 и SG5010.
Обмен совместим с DRONE_SIM / ANTENNA_STATE v2 из исходного README.
Дата реализации: 27.10.2026. Результаты проверок: `docs/TEST_REPORT.md`.

## Быстрый запуск Python

Требуется Python 3.11+ (Windows или Linux). В Windows можно запустить
`python/run_windows.bat` — он создаёт окружение, устанавливает зависимости и запускает GUI.
Ручной способ из папки `python`:

```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m drone_sim
```

Linux:

```sh
cd python
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m drone_sim
```

На Linux для Qt нужен графический сеанс и системные библиотеки xcb/OpenGL;
пользователю нужен доступ к последовательному порту (обычно группа dialout).
Приложение не требует Интернета после установки зависимостей.

## Проверить без Arduino

В одном терминале из `python/`:

```sh
python -m drone_sim.mock
```

В другом запустите GUI. Выберите `UDP (тестовый mock)`, адрес `127.0.0.1`,
порты 5005/5006, подключитесь. Mock использует примерный AZ-диапазон [-90,+90]°.
На вкладке «Антенна» подтвердите исходное положение и нажмите калибровку.
Это программный макет протокола, не модель динамики шаговика и не замена испытаний МК.

## Управление дроном

- «Установить координаты» телепортирует дрон в XYZ, не меняя выбранную траекторию.
- Выберите ручное движение, прямую или окружность, настройте параметры и нажмите
  «Применить траекторию / скорость», затем Start. Resume продолжает движение без
  переинициализации окружности. У окружности начальный угол отсчитывается от +X против часовой стрелки.
- Для W/A/S/D и Q/E включите флажок, выберите ручную траекторию, нажмите Start и
  кликните карту. Q — вверх, E — вниз. Диагональная скорость нормируется.
  Потеря фокуса карты обнуляет клавишную скорость. Для остановки всего движения — Stop.
- Pause и Stop продолжают поток телеметрии с нулевой скоростью; Stop не выключает приводы.
- Reset сбрасывает модель и историю карты; соединение остаётся открытым.
- Масштаб карты — колесо мыши, перемещение — перетаскивание. Сетка — 100 м.
- Цель: жёлтая линия, командный азимут: синий луч, измеренный: фиолетовый (только с датчиком).
  Серый след ограничен 3000 точками, чтобы не расходовать память бесконечно.
- Режим и масштаб модельного времени не влияют на реальную частоту TX.

## Сборка и загрузка прошивки

Предоставленные пользователем Servo, Arduino_FreeRTOS и GyverStepper включены
в `firmware/lib/` без изменения исходников. Дополнительно включён ArduinoJson 6.21.5.
Сохраняются лицензии авторов библиотек.

**Сначала настройте `firmware/AntennaTracker/config.h`.** По умолчанию
`ANTENNA_MECHANICS_CONFIGURED=0`: калибровка отклоняется, двигатели не запускаются.
Указанные там границы и импульсы — примеры, а не проверенные параметры вашей конструкции.

Вариант A — PlatformIO (из корня комплекта):

```sh
python -m pip install platformio
python -m platformio run -d firmware
python -m platformio run -d firmware --target upload --upload-port COM5
```

На Linux вместо COM5 используйте свой `/dev/ttyACM0`.
Зависимости периферии локальные; при первой сборке PlatformIO загружает AVR toolchain/core.

Вариант B — Arduino IDE:

1. Скопируйте четыре папки из `firmware/lib/` в каталог `libraries` своего sketchbook
   (либо установите исходные ZIP Servo, FreeRTOS, GyverStepper и ArduinoJson 6.21.5).
2. Откройте `firmware/AntennaTracker/AntennaTracker.ino`.
3. Выберите Arduino Mega or Mega 2560 / ATmega2560, правильный COM-порт.
4. Настройте `config.h`, выполните Verify, затем Upload.
5. Закройте Serial Monitor перед подключением Python.

PlatformIO увеличивает UART RX-буфер до 256 байт, TX до 128. Arduino IDE со штатным
RX=64 также обслуживается непрерывным чтением, но его производительность необходимо
проверить отдельно; рекомендуемый профиль сборки — PlatformIO либо CLI с теми же флагами.

## Первый запуск механизма

1. При отключённом питании приводов проверьте соединения по `docs/WIRING.md`.
2. Измерьте механические границы AZ с запасом до упоров, направление, число полушагов
   на оборот платформы, смещение севера. Установите безопасные EL_MIN/EL_MAX и PWM.
3. Укажите проверенные параметры в `config.h`, установите `ANTENNA_MECHANICS_CONFIGURED=1`,
   пересоберите и загрузите прошивку.
4. Физически установите AZ в известный развернутый механический угол, а EL в EL_INITIAL.
   Не проворачивайте редуктор с усилием: отсоединяйте нагрузку/муфту при необходимости.
5. Подайте питание и подключите UART 115200 через GUI. При открытии USB-порта Mega
   обычно перезапускается; дождитесь ответов. Приводы всё ещё заблокированы.
6. На вкладке «Антенна» введите известный механический AZ, поставьте флажок проверки,
   отправьте «Калибровать / разрешить приводы» и дождитесь ACK `ok=true`.
   Калибровка не ищет упор: она только присваивает счётчику шагов известное положение.
   Серво начинает удерживать EL_INITIAL. Неверное EL_INITIAL может вызвать физическое движение.
7. Начните с небольшого изменения AZ/EL. «Навести вручную» и кнопки ±5° переключают
   источник команд на ручной. Дрон при этом может продолжать свой полёт.
8. «Вернуть сопровождение дрона» переключает источник обратно. Перед переключением
   учитывайте, что новая цель может сильно отличаться от текущей.
9. DISARM блокирует дальнейшее движение с удержанием текущего расчётного положения
   и последней PWM-команды. После него для возобновления требуется новая калибровка.

Калибровка не сохраняется в EEPROM. После сброса/отключения питания нужна новая установка.
Сброс числа пакетов ПК не переинициализирует МК: при новом запуске Python с внешним
UART без автоматического RESET нажмите RESET на Mega, затем повторите калибровку.
В пределах одного запуска Python счётчики сохраняются при переподключении.

## Протокол и достоверность данных

- UART: 115200, 8N1, JSON + LF, ≤384 байт, TX по умолчанию 25 Гц.
- Ручные углы передаются существующим DRONE_SIM v2 через виртуальную цель R=100 м.
  На EL=90° сохраняется явно заданный ручной AZ, хотя координаты близки к оси Z.
- CALIBRATE/DISARM — отдельное документированное расширение ANTENNA_CONTROL v1;
  обязательные сообщения v2 не изменены. См. `docs/PROTOCOL_EXTENSION.md`.
- `source_seq` подтверждает обработку, **не достижение цели**.
- `cmd_*` — конечные цели управляющей логики с ограничениями; при STALE/DISARM это
  удерживаемая оценка AZ и последний выданный EL. Промежуточное движение не является измерением.
- `act_*=null`, `act_*_valid=false`: датчиков положения в этом составе оборудования нет.
- Командная ошибка рассчитывается по истории `source_seq`, фактическая — относительно
  текущей цели и только при действительном измерении. Устаревшие ошибки не вычисляются.
- CSV сохраняется по кнопке на вкладке диагностики в выбранное пользователем место.

## Архитектура и ограничения

Python: отдельный поток `Engine` обновляет модель фиксированным шагом 20 мс и обслуживает
UART/UDP по монотонным часам; GUI обновляется раз в 40 мс. Очередь управления потоком,
блокировки и кольцевая история исключают смешивание источников и частично обновлённые пакеты.
Неудачная/частичная запись UART разрывает соединение; старые кадры не ставятся в очередь.

Mega: две равноприоритетные FreeRTOS-задачи — UART и управление приводами — постоянно
передают выполнение через taskYIELD. Нет ожидания полного вращения, delay или блокирующей
Serial.write: выдача ограничена availableForWrite. GyverStepper.tick() вызывается часто,
его тактирование не зависит от 15-мс тика FreeRTOS. Servo обслуживает импульсы своим ISR.
На Mega первый Servo использует Timer5; FreeRTOS — WDT; millis/micros — Timer0.

Задачи используют FIFO запросов; при переполнении пакет отклоняется целиком. Входная
строка при переполнении сбрасывается до LF. Ошибочные/старые пакеты не продлевают watchdog.
Проверяется также следующий шаг мотора: торможение/смена направления внутри GyverStepper
не разрешают выход за механическую границу.

При STALE >250 мс шаговик останавливается, выдача новых целевых импульсов серво прекращается,
но удерживается последний PWM. Реальную мгновенную остановку SG5010 без датчика и аппаратного
отключения гарантировать невозможно. При потере шагов программная координата становится
неверной: устраните причину и повторите калибровку. Концевиков и энкодеров здесь нет.
Система не предназначена для работы без присмотра до аппаратных испытаний.

Расхождения исходных ТЗ и принятые решения: `docs/DECISIONS.md`.

## Тесты

Из `python/`:

```sh
python -m unittest discover -s tests -v
python tests/benchmark.py --kind UART --seconds 60
python tests/benchmark.py --kind UDP --seconds 60
```

Для запуска benchmark из файла нужен `PYTHONPATH=.` (Linux: `PYTHONPATH=. python ...`;
PowerShell: `$env:PYTHONPATH='.'`). UART benchmark использует POSIX PTY и запускается
на Linux; он не подтверждает физические 115200 бод или быстродействие AVR.
Для Windows и реального Mega используйте `tools/hardware_check.py` по инструкции в нём.
